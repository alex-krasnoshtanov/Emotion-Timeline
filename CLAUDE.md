# Working in this repository

A ground-up rebuild of a university NLP project: turning a Russian-language video
into a per-scene emotion timeline, plus the dataset, model selection and error
analysis that had to happen before the classifier meant anything.

It is a portfolio repository. A reader decides in about a minute whether the work
is real, so **every number on a page must be traceable to something committed**.
That constraint drives most of the rules below.

## The one rule that matters

**Never publish a number that cannot be reproduced or cross-checked.**

This is not abstract. The original coursework reported 0.61% word error rate for
AssemblyAI. It was arithmetically correct and meant nothing, because it summed
the first 240 rows of two spreadsheets whose rows cover different amounts of
audio. The real figure over a shared window is 0.81%. Finding that took ten
minutes and it was the single most valuable thing in the rebuild.

So when you add a result:

1. Commit the inputs it comes from, under `benchmarks/`.
2. Make a command recompute it (`emotion-timeline wer`, `errors`, ...).
3. Write a test that asserts the published figure.
4. If the raw data is gone and only a summary survives, say so in the doc, and
   add consistency checks plus an independent cross-check — see
   `check_consistency()` and `test_class_error_rates_match_the_model_card_recalls`.

## Invariants that must not regress

- **Speech-to-text is compared over a time window, never a row count.** The
  systems segment differently (797 segments against 316 for the same recording).
  `wer.compare()` takes `start_s`/`end_s` for this reason, and
  `test_the_window_is_what_makes_it_a_comparison` asserts the row-count version
  gives the wrong answer. Do not add a row-count path.
- **Figures are generated, never hand-edited.** After touching anything under
  `benchmarks/error-analysis/`, run `emotion-timeline figures --out assets` and
  commit the result. CI regenerates and fails if `assets/` is stale.
- **`check_consistency()` gates rendering.** If a report's numbers contradict
  each other, `emotion-timeline figures` exits non-zero rather than drawing the
  contradiction as a picture. Keep it that way.
- **CI runs on pull requests, not only on `main`.** The sibling repo DSL-Learning
  gets this wrong: its frontend compiles only in the image build on `main`, so a
  breaking change passes review and fails after merge.

## Layout

```
benchmarks/           committed inputs every published number derives from
  stt/                annotated transcripts (hand-marked S/I/D per segment)
  error-analysis/     recorded evaluation statistics
src/emotion_timeline/
  stt/                transcriber adapters + the WER harness
  analysis/           error analysis and figure rendering
  cli.py              one subcommand per stage
docs/                 one chapter per stage, each ending in what it does NOT show
assets/               figures, regenerated by `emotion-timeline figures`
tests/                the arithmetic, and the mistakes worth pinning
```

## Commands

```bash
uv sync --extra dev
uv run pytest
uvx ruff@0.6.9 check . && uvx ruff@0.6.9 format --check .

uv run emotion-timeline wer --window 0:00-18:09   # speech-to-text comparison
uv run emotion-timeline errors                    # where the classifier fails
uv run emotion-timeline figures --out assets      # regenerate every figure
```

## Conventions

- Python 3.12+, `uv` first, pip documented as the fallback.
- ruff, line length 100. `filterwarnings = ["error"]` — a warning fails the suite.
- The **core install stays light**: numpy, pandas, matplotlib, scipy and nothing
  else. Anything needing a GPU or a paid API is an extra (`stt`, `model`,
  `demo`). Someone who only wants to read the results should not download torch.
- Docstrings explain *why*, not *what*. The module docstring in `stt/wer.py` is
  the house style: it explains why WER is recombined rather than aligned, because
  that is the non-obvious part.
- Prose is British English and avoids "not X, but Y" constructions.

## Never commit

- **Client material.** The original group repo holds labelled transcripts
  supplied by the Content Intelligence Agency. Those stay out.
- **Media.** The upstream repo carries ~700 MB of downloaded YouTube audio. One
  short public clip for the demo is the ceiling.
- **Datasets.** The 428k-row training set is rebuilt from public sources by
  `build-dataset`, never committed — it is ~174 MB.
- **Model weights.** They ship as GitHub release assets with a recorded SHA-256,
  verified on download. Reuse the pattern in `CV-Pipeline-Deployment-Platform`'s
  `cv_pipeline/weights.py` rather than writing a new one.

Keep the repository small. A sibling repo carries 104 MB of git history for 92
files; that is the mistake not to repeat.

## Local gotcha

On this machine, bash heredocs eat backslashes: `\\` in a quoted heredoc arrives
as `\`. This has silently corrupted LaTeX line breaks and Python string literals
more than once. **Write files containing backslashes with the Write tool**, or
build them via `chr(92)`, rather than through a heredoc.
